# 组件预览真实性核查

本次核查覆盖当前目录的 82 个组件页面、18 个状态示例，以及旧版组件工作台的渲染入口。

## 已发现并修复

- Timeline 和 LayersPanel 没有可运行文档示例，预览静默回退到手写的旧演示。现在使用公共 `auricui/studio` 入口导出的真实组件，示例文件为 `src/docs/examples/studio.tsx`。
- 危险确认弹窗的预览和展示代码走不同路径。现在使用同一个 `DangerConfirmExample`。
- 旧工作台使用独立的演示和代码片段。现在共用文档 Preview 与生成代码；移除了不能控制这些真实示例的旧属性配置面板，保留主题、设计变量、收藏等工作台能力。
- Inspector 示例的间距回调为空，MetricField 的预览回调为空。现在接入本地状态和反馈。
- 删除旧的 Demo 渲染器，防止再次被用作文档预览的兜底。

## 示例能力边界

时间轴使用真实 Timeline，接入本地选择、定位、时间推进、删除及撤销/重做；没有接入媒体播放、拖动裁剪、导出或后端保存。页面明确写出范围，完整编辑操作在专业编辑工作台演示。

图层面板使用真实 LayersPanel，本地实现图层树、选择、显隐、锁定、排序和关闭/重开，不连接真实舞台。

标记为“组合示例”的排版、图标按钮、加载、素材展示不是同名公共组件，不按公共组件宣称。

## 自动检查

`npm run check:docs` 检查：

1. 每个目录页面有明确注册的示例，禁止静默回退。
2. 非组合示例从对应公共入口导入并实际渲染声明的组件。
3. 主预览、状态预览的函数实现与生成的可复制代码一致。
4. 旧工作台共用文档入口，不调用旧 Demo 或 snippet。
5. 所有生成示例使用实际打包的 npm 成品进行严格 NodeNext 类型检查。

本次 `npm run build`、`npm run check:docs` 通过；109 份文档示例与 13 份 Skill 示例通过成品包编译检查。
